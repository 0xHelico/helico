# Full 1inch: the whole swap path, and the data behind it

11 September 2026. Written before the code, as `CLAUDE.md` requires.

## Why now

We have a 1inch Business API key. Until today the app used exactly one 1inch surface — our own
Aqua app, `HelicoMandateSwap`, plus the redeployed SwapVM router — and when Aqua had nothing to
fill against, the swap fell through to **Uniswap v4**. Uniswap has not been a submitted track
since 7 September (#125). So the product's most visible action currently ends at a protocol we do
not submit, while the partner we do submit sits behind a refusal.

The key removes the reason that compromise existed. It was never a design preference: the
aggregation API needs authentication, and we had none.

## What is being claimed, and what is not

This does not claim the 1inch track qualifies. `CLAUDE.md` records that 1inch declined to bless
the design and called it general, and nothing here changes that. What changes is the amount of
1inch in the product, which is a fact about the code rather than a judgement about the prize.

## Measured before writing any of this

Every endpoint below was called with the real key against Arbitrum One, and these are the
answers, not documentation quotes:

| Call | Answer |
|---|---|
| `GET /swap/v6.1/42161/quote` 0.1 WETH → USDC | `{"dstAmount":"246061367"}` — 246.06 USDC |
| `GET /swap/v6.1/42161/approve/spender` | `0x111111125421ca6dc452d289314280a0f8842a65` |
| `GET /price/v1.1/42161/<WETH>?currency=USD` | `2469.61926272` |
| `GET /swap/v6.1/42161/swap` without an allowance | `NOT_ENOUGH_ALLOWANCE`, with the spender named |

That last one matters for the plan: the aggregation API refuses to build a transaction until the
allowance exists, so the card has to send the approval first and ask again — the same two-step
shape the Aqua path already has, not a special case.

## Where the key lives

**Server-side only, and never in the browser.** No `NEXT_PUBLIC_` prefix, ever: that prefix
inlines a value into the client bundle, and a bundled key is a public key.

- `apps/app/.env.local` and `apps/be/.env`, both gitignored, for local work
- Coolify and GitHub secrets for the deployments
- `.env.example` files carry the **name** and nothing else

The dapp reaches 1inch through a Next route handler that adds the header on the server. The
handler is a narrow proxy — a fixed allowlist of upstream paths, not a pass-through — because an
open proxy in front of an authenticated API is a way to spend someone else's quota.

## The work, in order

### 1. `packages/plugins/1inch` gains an `api/` module

Per `CLAUDE.md`, off-chain partner code lives in the plugin and apps consume it. The module holds
the request building and the response types for:

- **Swap (classic aggregation)** — `quote`, `swap`, `approve/spender`, `approve/transaction`
- **Spot price** — `price/v1.1`
- **Balances** — `balance/v1.2`

It takes a `fetch`-shaped function and a base URL rather than reading `process.env` itself, so it
is callable from the route handler, from the Go backend's own client, and from a test with a
stubbed fetch.

### 2. The Uniswap fallback becomes the 1inch fallback

`apps/app/components/swap-card.tsx` currently reads:

```
Aqua → (on refusal) → Uniswap v4
```

and becomes:

```
Aqua → (on refusal) → 1inch aggregation
```

The refusal reason is still printed, because that was the honest part of the current card and it
stays: a person is told why their own position could not pay before being shown the route that
could.

`@helico/plugin-uniswap` is **not deleted**. `FEEDBACK.md` and its tests stay exactly as they
are — `CLAUDE.md` says the v4 code stays tested — it simply stops being in the swap path.

### 3. Portfolio reads come from 1inch where 1inch is better

"Check my portfolio" currently reads two token balances the app knows about. The Balance API
answers for every token an address holds, in one call. The account's own reads stay where they
are load-bearing — `useAccountState` decides whether the account is open and where its capital is
lent, and that is a contract question, not a market-data one.

### 4. Chainlink stays where it is

Dollar sizing keeps reading the Chainlink feed and does **not** move to 1inch's spot price. The
figure a person signs is read by the wallet that signs it, from a feed with a heartbeat, and one
of our three tracks is Chainlink. Spot price is worth having for display; it is not worth having
for a signature.

### 5. `Swapped` joins the subgraph

1inch's own Aqua documentation, under Data & Analytics, says:

> A hosted subgraph is not currently available. Build a reference indexer over the five
> registry/router events keyed on `(maker, app, strategyHash)`.

Ours indexes four of those five — `Shipped`, `Docked`, `Pulled`, `Pushed` — and not `Swapped`.
Adding it completes the set the vendor describes, and the quote above is better evidence for the
Graph track than our own assertion that the data has no on-chain answer: the protocol's
documentation says it too.

## How each piece is verified

Nothing here is finished by looking at it.

- **A quote that is not a number nobody checked.** The aggregation quote is compared against the
  Chainlink feed within a tolerance, the same check `rehearse-ship.ts` already does. A route that
  returns 6.7e150 of something has to fail a test, because it already did once
- **A fill on a fork.** `fork-chat-actions.ts` gains a swap that Aqua refuses and 1inch fills,
  with the taker's balance read before and after. The stubbed `Fillable` query stays the only
  stub; the aggregation call is real, against the real API, and the transaction is signed by a
  generated wallet on anvil
- **The key is not in the bundle.** A test greps the built client chunks for the key's value and
  fails if it is there. This is the check that would be worth having even if everything else were
  green, and it is unsatisfiable if the claim is false — which is the standard `CLAUDE.md` sets
- **The proxy refuses what it does not allow.** A request for an upstream path outside the
  allowlist is answered 404 by us, not forwarded

## What is deliberately not in this plan

- **Fusion and cross-chain.** Intent-based and cross-chain swaps are a larger surface than two
  days can verify, and an unverified integration is a disqualification rather than a deduction
- **The Orderbook API.** Limit orders through 1inch's own book would compete with the mandate
  rather than complete it: the mandate is the thing this product is about, and it lives in our
  Aqua app
- **The MCP server in the product.** It is a development tool, configured outside the repository
  so no key is committed. The product talks to the REST API
