The problem

Idle capital is the price
of being able to fill.

1inch Aqua leaves a maker's tokens in their own wallet and serves a fill from it at the moment it fills. That is the good part. It also means the wallet has to be ready — and a wallet kept ready earns nothing.

put it to work

Supply everything to Aave and the yield is real — until a mandate is filled against a wallet that no longer holds the tokens, and the fill fails.

keep it liquid

Hold everything in the wallet and every fill succeeds — while the capital earns nothing for the time nobody is filling against it.

the buffer

Not a percentage somebody picks. A number that changes every time a mandate is shipped, because what a maker could be asked to pay is what their live mandates add up to.

How it works

Three reads, one decision,
one signature.

1,000liquid, ready to fill
4,000working in Aave v3

Read

The account's balances, every permitted market's rate and free liquidity, and what live Aqua mandates could still demand.

Decide

Inside the enclave, against a policy nobody else can read: the target split, the liquid floor, and the smallest move worth paying gas for.

Sign

An EIP-712 statement bound to the account, the policy hash and a nonce. The signing key exists only inside the enclave.

The agent cannot take anything. Neither call it may make has a recipient parameter — one credits the account, the other returns to it. A compromised agent can move a maker's money between markets the maker allow-listed, and nowhere else.

A bug worth a slide

Every run failed. Three good
theories were wrong.

The deployed workflow failed at secret retrieval on every single run. It never reached its own logic — so "it holds correctly" was describing intent, not behaviour.

The batch was too large

Eleven and ten failed identically. Only the count changed.

The namespace was wrong

A run with it set explicitly failed the same way — and the error had been printing the namespace all along.

The manifest was incomplete

workflow unchanged; re-deployment skipped proved the manifest is not part of the deployed artifact.

getSecret(request) {
  const c = this.getSecrets([secretRequest])   // a batch of one
}
const id = this.nextCallId; this.nextCallId++  // inside getSecrets

Splitting into one call per secret — the shape Chainlink's own reference recommends — made call 0 succeed and call 1 fail, twice, on one binary. There is no separate singular path: every retrieval is a batch, and what separates them is the callback id. The DON answers one retrieval per execution. Eleven values now travel as one.

What is not proven

The honest half.

Written down because the difference between measured and inferred is the difference between evidence and a claim.

not yet

An account on the live chain

The factory is live and permissionless and nobody has called it. So the deployed workflow reaches its logic and holds, correctly, every run. The first person to press the button is the one it manages — no redeploy.

not yet

A signed move landing on mainnet

Everything downstream of an account existing is proven on a fork and no other way. The CRE simulator is not a TEE, and says so while it runs.

measured

The enclave runs on the DON

Every five minutes, reading its policy from the Vault DON before anything else. A run that completes is a run that got its secret.

inferred

Attestation

Chainlink's reference states execution completes only after DON consensus verifies the enclave's attestations. We have not read an attestation document ourselves — this follows from the documented mechanism plus a run that completed.

There has been no professional audit. Twelve automated reviewers went over the contracts, then six more. That is not an audit, and nothing here calls it one.
